# 01 · 项目定位与参考项目

## 需求背景

规划中的平台包含七个功能模块：

**数据集成 · 数据开发 · 数据调度 · 数据资产 · 数据地图 · 数据服务 · 智能问数**

核心诉求：像 SQLBot（ChatBI）一样，**通过 AI 对话直接创建数据同步任务、ETL 任务、定时调度、数据查询**——即 AI-Native 的数据平台，而不是"带聊天框的传统数据平台"。

## 参考项目分析

| 项目 | 可借鉴 | 局限 |
|---|---|---|
| **AllData**（alldatacenter/alldata，GPL-3.0） | "自研壳 + 集成开源组件"的组装思路：Java/Spring Boot + Vue，粘合 DataX / DolphinScheduler / SeaTunnel / OpenMetadata 等十几个组件 | 纯人工配置界面，AI 能力弱；组件堆得太杂、每个都浅尝辄止，维护成本爆炸 |
| **SQLBot**（dataease/SQLBot，GPLv3 + 附加条款） | NL2SQL + RAG（元数据/术语库/few-shot 检索）持续校准、"越问越准"、MCP 集成、对话式 BI | 只做了"问数"这一层，没有生产任务创建能力 |

> AllData 的教训：开源件堆了十几个（SeaTunnel、Dinky、StreamPark、Datavines、Datart……），每个都浅尝辄止。
> 本项目的对策：**每个模块都要回答"元数据怎么进、账号怎么通、AI 怎么调"三个问题，回答不了就先不上**。

## 平台定位

> **AllData 的模块完整性 + SQLBot 式的 AI-Native 交互。**

关键差异化：不是每个模块套一个聊天框，而是 **AI Agent 作为横切层**——把平台所有 service 能力封装成 MCP Tools，模块每加一个，AI 能力自动扩展；未来还可被 Claude / Dify 等外部 Agent 直接调用。

## 核心设计思想

把 SQLBot 的"NL→SQL"推广为 **"NL→结构化任务配置"**：

```
用户自然语言
   │
   ▼
AI 生成结构化 JSON 配置（非代码文件、非 DataX 原文、非 DAG 文件）
   │
   ▼
校验器（JSON Schema / 连通性测试 / 字段类型映射 / 试读样本数据）
   │
   ▼
落配置中心（status = draft 草稿态）
   │
   ▼
人工确认（对话内点"确认上线"，HITL）
   │
   ▼
模板渲染成 DataX JSON / Airflow DAG → 上线
```

### 一条架构铁律

**AI 永远不直接产出最终执行物**（不写 DAG 文件、不把 DataX JSON 写到磁盘）。
AI 只负责往配置中心写一条结构化记录，渲染由平台代码完成。

三个收益：

1. **可控** —— 配置过 Schema 校验才能入库
2. **可审计** —— 每个任务配置有版本、有生成者（人 or AI）
3. **可回滚** —— 改配置即改任务，历史版本可回退
