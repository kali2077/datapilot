# 03 · 开源组件评估（回退备选 + 协议合规参考）

> **当前决策是平台层全自研，本文档用途：**
> ① 各模块确实没有对口开源时的佐证；
> ② 自研受阻时的回退备选（首选 OpenMetadata）；
> ③ 引入任何开源件前的 License 合规检查清单。

## 一、模块 → 开源映射总览

| 模块 | 首选开源 | 备选 | License | 判断 |
|---|---|---|---|---|
| 数据资产 + 数据地图 | **OpenMetadata** | DataHub | Apache 2.0 | 一套系统覆盖两个模块（目录/标签/术语表 + 搜索/血缘） |
| 数据查询 | **Superset（SQL Lab）** | CloudBeaver / Archery | Apache 2.0 | 即席查询 + 白送 BI 看板 |
| 数据开发 | 自研薄壳 + CloudBeaver 内嵌 | Taier / Dinky（实时） | — | 不建议整套搬 Taier（低频维护 + 自带调度体系与 Airflow 冲突） |
| 数据服务 | **无对口开源，轻量自研** | Cube.js / SuperSonic 语义层 | — | 唯一没有开源单品的模块 |
| 智能问数 | SQLBot 或 **SuperSonic** | DB-GPT / WrenAI | 见下表 | SuperSonic = ChatBI + 语义层合一 |

## 二、逐模块要点

### 资产 + 地图：OpenMetadata（回退首选）

- 目录、搜索、**血缘**、术语表、打标、Owner、质量面板全有；Python 采集器生态丰富
- REST API 完整，可直接封装为 AI 工具（search_tables / get_lineage / get_columns）
- 自写部分：Doris 采集器（可用 MySQL 连接器部分兼容）、DataX 血缘推送
- 备选 DataHub 血缘更强但部署重（Kafka/ES/GraphDB），中等团队选 OpenMetadata

### 数据查询：Superset SQL Lab

- Web 即席查询 + 保存查询 + 导出 + 出图；Doris/StarRocks 有官方 SQLAlchemy 对接
- 备选 CloudBeaver（偏工程师多源 SQL 工作台）；Archery（查询带工单审核 + 脱敏场景）

### 数据开发：开源全家桶的两个坑

- **Taier**（Apache 2.0）：功能全但已低频维护（官方重心转商业产品），且自带调度体系，**与 Airflow 选型冲突**
- 结论：薄自研（任务配置中心 + Airflow 动态 DAG），SQL 编辑器可内嵌 CloudBeaver 或 Monaco 自写；实时开发二期再加 Dinky（只管 Flink，不冲突）

### 数据服务：为什么没有对口开源

国内数据中台语境的"数据服务"（SQL 模板化 → 带鉴权/限流/审计的 API）没有标杆开源。
候选项目都只解决单点：

| 项目 | 语言 | 定位 | 为何不能当底座 |
|---|---|---|---|
| Datasette | Python | SQLite 发布成 Web+API | 只支持 SQLite |
| CKAN | Python | 开放数据门户 | 面向"数据开放"场景，太重 |
| Redash Query API | Python | 保存查询自带 API | 可当轻量服务但维护放缓 |
| sandman2 | Python | DB 自动生成 REST CRUD | 无模板/鉴权/限流/审计 |
| magic-api / dbApi(Datavane) | Java | 低代码 SQL→API | 语言不符，但**功能清单最值得抄** |

→ 结论：自研，设计见 05 文档。

### 智能问数：SQLBot vs SuperSonic

- SQLBot：更快落地（嵌 MCP / iframe），但协议有红线（见下）
- **SuperSonic**（腾讯音乐，Apache 2.0）：ChatBI + Headless BI 语义层合一——问数走模型、API 服务也走模型，同时覆盖"智能问数"和"数据服务"的语义底座；代价是建模成本高
- 策略：问数先做简版自研（query_data），需要统一指标口径时再评估 SuperSonic / Cube

## 三、License 协议核查（定稿清单全部 Apache 2.0）

| 组件 | 协议 | 二开/商用 | 关键限制 |
|---|---|---|---|
| Doris / Airflow / DataX / APISIX | Apache 2.0 | ✅ 可改可商用可闭源衍生 | 保留 LICENSE/NOTICE 声明 |
| OpenMetadata / Superset / SuperSonic / DB-GPT | Apache 2.0 | ✅ 可换皮去 logo | 商标不得冒用 |
| CloudBeaver Community | Apache 2.0 | ✅ 可二开 | ⚠️ 白标/深度嵌入/部分驱动是企业版卖点，商用换皮有灰区；建议独立子域名挂载 |
| Taier / Dinky | Apache 2.0 | ✅ | 上游低频维护，二开 = 自己养 |
| **SQLBot** | **GPLv3 + 附加条款** | ⚠️ | ①不得替换 Logo/版权信息 ②对外分发需开源衍生代码 ③内部使用不触发开源义务 |
| **AllData（参考项目）** | **GPL-3.0** | ⚠️ | **只学架构，别抄代码**——抄了整个平台必须 GPL 开源 |
| Chat2DB 3.x | 自定义限制协议 | ❌ | 2.x 才是 Apache 2.0，3.x 已收紧 |

**协议判断一句话版：**
- Apache 2.0 / MIT：改、嵌、商用、闭源都行，保留版权声明即可
- GPL / AGPL：改完**对外分发**须开源衍生代码；**公司内部使用**不触发
- 附加条款（SQLBot/DataEase 类）：即便内部使用，"不许换 logo/版权"依然生效

> ⚠️ 协议以各仓库 LICENSE 当前版本为准（项目会换协议，Chat2DB 是前车之鉴）。
> 引入新开源件前自检三问：**元数据怎么进？账号怎么通？AI 怎么调？** 答不了就先不上。
