# 07 · 总体 PRD（v1.0）

> 状态：PRD 定稿，可启动开发。周期计划见 08 文档。
> 产品代号：暂定 **DataPilot**（占位，待定名）。

## 1. 产品概述

### 一句话定位

面向数据团队全流程的 **AI-Native 数据平台**：引擎用成熟开源，平台全自研，自然语言对话贯穿建任务、跑调度、查数据、管资产的全过程。

### 产品目标（可衡量）

| # | 目标 | 基线（传统方式） | 目标 |
|---|---|---|---|
| G1 | 建一个定时同步任务 | 配置 DataX + 写 DAG + 调试，约 30-60 分钟 | 对话 1 分钟创建，含试跑验证 |
| G2 | 分析师自助取数 | 提工单等工程师，半天起 | 对话即席查询，秒级返回 |
| G3 | 日常调度运维 | 登录 Airflow 看日志 | 80% 运维操作（重跑/暂停/查错）对话完成 |
| G4 | 数据可发现 | 问同事"这数在哪" | 数据地图搜索 + 血缘自助追溯 |

### 成功指标

- M1 后：端到端"一句话建同步任务"成功率 ≥ 90%（含澄清反问后）
- M2 后：ETL 任务创建中 AI 生成 SQL 一次通过率 ≥ 70%（其余经编辑器修改）
- 问数：Top 50 常用问题准确率 ≥ 85%，元数据覆盖率 100%（核心表注释齐全）

## 2. 用户角色

| 角色 | 典型场景 | 核心功能 |
|---|---|---|
| 数据工程师 | 建集成/ETL/调度，排查失败 | 集成、开发、调度 + AI 建任务 |
| 数据分析师 | 找数、取数、出数 | 数据查询、智能问数、数据地图、数据服务订阅 |
| 业务人员 | 看数 | 智能问数（限定授权范围） |
| 平台管理员 | 管数据源、账号、权限、审计 | auth、数据源管理、审计查询 |

## 3. 需求范围与优先级

| 优先级 | 模块 | 说明 |
|---|---|---|
| **P0（MVP）** | auth、数据源管理、元数据核心、数据集成、数据调度、AI 对话入口（query_data / create_sync_job） | M1 里程碑 |
| **P1** | 数据开发（ETL 编排）、智能问数完善（RAG+图表）、调度运维、任务级血缘 | M2 里程碑 |
| **P1.5** | 数据资产、数据地图、数据服务（apigw） | M3 里程碑 |
| **P2（可选）** | 数据质量规则、API 定时预热、行级权限、实时链路（Dinky/SeaTunnel）、OpenMetadata 回退 | GA 后按需 |

### 明确不做（v1 范围外）

- 实时计算（Flink CDC / 海豚实时）、流批一体
- BI 报表看板（问数出图覆盖轻量场景，重报表后续单议）
- 多租户 / K8s 部署 / 高可用集群（单机 Docker Compose 起步）
- 机器学习平台、标签工厂

## 4. 功能需求

### FR-AUTH 认证与权限（P0）

- 用户登录（JWT）、RBAC（admin / engineer / analyst / viewer 四角色起步）
- 资源级授权：数据源、任务、API 按角色+Owner 控制
- **AI 以登录用户身份执行所有工具**，无独立越权通道（红线，见 06 文档）
- 验收：analyst 角色无法创建任务/查看无授权数据源

### FR-SRC 数据源管理（P0）

- 支持 MySQL / Doris 两类数据源 CRUD + 连通测试 + 凭据加密存储
- 数据源 = 集成、开发、查询、服务各模块的统一入口对象
- 验收：新增数据源 30 秒内完成并测试连通

### FR-META 元数据核心（P0）

- 表/字段清单自动采集（SQLAlchemy inspector 定时采集，任务入 Airflow）
- 字段注释/业务描述人工补录，采集不覆盖人工字段
- 验收：新接入数据源 5 分钟内元数据可见

### FR-INTEG 数据集成（P0）

- 结构化同步任务配置（源/目标/字段映射/增量策略/调度）→ 渲染 DataX JSON
- 校验链：JSON Schema + 连通性 + 类型映射（知识库表）+ 试跑 100 行预览
- 目标表不存在时按源表自动建表建议（含 Doris 分区建议）
- 状态机：draft → published → offline；版本可回滚
- 验收：MySQL→Doris 全量/增量两类任务可创建、试跑、上线、次日自动执行

### FR-SCHED 数据调度（P0 核心 / P1 运维）

- 配置驱动动态 DAG：factory 模板 + Airflow REST API，AI/用户永不直接写 DAG 文件
- 依赖管理：任务可声明 upstream，跨任务依赖基于血缘推荐（P1）
- P1 运维：实例列表、日志查看、重跑、暂停/恢复、失败告警（邮件/webhook）
- 验收：调度变更（改 cron/加依赖）通过配置生效，无需触碰 Airflow 界面

### FR-DEV 数据开发（P1）

- SQL 任务配置（Doris 引擎）：编辑器 + sqlglot 校验（禁 DDL/DML）+ EXPLAIN 试跑
- 工作流编排：SQL/DataX/Python 节点组成 workflow，配置 upstream
- 任务级血缘：INSERT 目标表 ← SQL 源表，自动解析入 meta
- 验收：三层明细模型（ods→dwd→dws）依赖链可创建并按依赖顺序执行

### FR-QUERY / FR-CHAT 智能问数（P0 基础 / P1 完善）

- P0：`query_data` 只读即席查询（自动 LIMIT + 超时熔断）+ 结果表格
- P1：元数据/术语 RAG 注入、few-shot 样例库、结果自动出图（柱/线/饼）
- 验收：自然语言问数返回正确表格，附可展开的 SQL 与数据来源说明

### FR-ASSET / FR-MAP 数据资产与地图（P1.5）

- 资产目录：库/表/字段 + 标签 + Owner + 使用说明；变更留痕
- 数据地图：关键词搜索（表名/注释/标签倒排索引）+ 血缘图可视化
- 验收：新同事不问人，通过地图找到目标表并理解上游来源

### FR-APIGW 数据服务（P1.5）

- 设计见 05 文档：SQL 模板 → API，AK/SK + 授权 + 限流 + 审计 + 缓存
- 验收：一个 API 从创建到第三方应用调用成功 ≤ 10 分钟

### FR-AI 对话横切能力（P0 起）

- Agent loop（Function Calling），工具即 service 方法（清单见 06 文档）
- 确认流：create 类工具只产草稿 + 任务卡片，用户确认才上线（HITL 红线）
- 上下文：会话历史 + 元数据 RAG 注入；生成物全部留痕（谁/何时/AI or 人工）
- 验收：全部工具在无 LLM 情况下可通过 UI 等价操作（AI 是增强，不是唯一入口）

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 凭据加密存储；SQL 只读校验；AI 权限=用户权限；操作审计全覆盖 |
| 性能 | 问数/查询默认 30s 超时 + 1000 行上限；API 单次 row_limit 可配 |
| 可部署 | 单机 Docker Compose 一键起；配置与数据卷分离 |
| 可观测 | 平台日志结构化；任务失败告警可达（邮件/webhook） |
| 可恢复 | 任务配置版本化可回滚；MySQL 每日备份 |
