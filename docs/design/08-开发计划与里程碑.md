# 08 · 开发计划与里程碑

## 基本假设

- **基线：单人全栈**（后端+前端）+ AI 辅助编码，16 周到 GA
- 若有 1 名前端协作：约 11-12 周（后端关键路径不变）
- 工作量以"人周"标注，可按人力换算
- 每周末产出可运行版本（周交付原则），避免长分支

## 阶段计划（16 周）

### Phase 0 · 地基（W1-W2，2 人周）

| 周 | 后端 | 前端 | 交付物 |
|---|---|---|---|
| W1 | monorepo 脚手架 + docker-compose（MySQL/Doris/Airflow/DataX/Nginx）+ auth（JWT+RBAC 表+登录） | Vue3 骨架：登录+布局+路由 | 一键起环境，可登录空壳系统 |
| W2 | 数据源管理 CRUD+连通测试+凭据加密；meta 核心表（数据源/库/表/字段） | 数据源管理页 | 数据源可配可测，元数据模型落库 |

### Phase 1 · MVP：一句话建同步任务（W3-W6，4 人周）

| 周 | 后端 | 前端 | 交付物 |
|---|---|---|---|
| W3 | integ：DataX 模板渲染 + 校验链（Schema/连通/类型映射/试跑100行）+ 类型映射知识库表 | — | API 级创建同步任务可用 |
| W4 | sched：factory DAG + Airflow REST 封装 + 配置→DAG 渲染 + 定时执行 | 集成任务列表/详情/试跑预览 | 同步任务可定时自动跑 |
| W5 | ai：Agent loop + `query_data` + `search_metadata`（先只读工具） | 对话框（流式 + 消息历史） | 对话查数可用（≈智能问数 v0） |
| W6 | `create_sync_job`：草稿 + 反问澄清 + 确认卡片 + 上线联动 sched | 任务卡片组件 + 确认交互 | **M1** |

**M1 验收演示脚本**：登录 → 配置 MySQL 业务库 → 对话框输入"把 orders 表每天 2 点同步到 Doris ods 库" → AI 反问增量策略 → 确认 → 试跑 100 行成功 → 点确认上线 → Airflow 次日 02:00 自动执行成功。

### Phase 2 · 数据开发 + 问数完善（W7-W10，4 人周）

| 周 | 后端 | 前端 | 交付物 |
|---|---|---|---|
| W7 | dev：SQL 任务配置 + sqlglot 校验 + EXPLAIN 试跑；`create_etl_job`（单任务） | SQL 编辑器（Monaco）+ 任务配置页 | 对话建 SQL 任务 |
| W8 | 工作流编排（multi-node + upstream）+ 任务级血缘解析入 meta | 工作流画布（简单 DAG 视图） | 多节点依赖编排 |
| W9 | 调度运维：实例/日志/重跑/暂停 + 失败告警；运维工具（run/pause/rerun） | 运维页 + 告警配置 | 运维操作对话化 |
| W10 | 问数完善：元数据 RAG 注入 + 术语表 + few-shot + 出图 | 问数图表渲染 | **M2** |

**M2 验收演示脚本**：对话"基于 ods_orders 做 dwd 订单明细，剔除测试账号，每天跑" → AI 生成 SQL（编辑器可改）→ 血缘挂依赖 → EXPLAIN + 试跑 → 确认上线 → 次日按依赖顺序执行；业务人员对话问"上月 GMV 多少"返回数字+图。

### Phase 3 · 资产 / 地图 / 数据服务（W11-W14，4 人周）

| 周 | 后端 | 前端 | 交付物 |
|---|---|---|---|
| W11 | 资产：采集入目录 + 标签/Owner + 搜索（倒排索引） | 资产目录页 | 资产可浏览可搜 |
| W12 | 地图：表详情 + 血缘图 API（基于 W8 血缘数据） | 表详情页 + 血缘图（AntV G6） | **地图可用** |
| W13 | apigw：五表 + API CRUD + 执行链路（AK/SK/限流/审计/缓存，见 05 文档） | API 管理页 | 数据服务可发布可调用 |
| W14 | `publish_api` 工具 + API 文档页 + 审计查询页 | 审计/文档页 | **M3** |

**M3 验收演示脚本**：地图搜"订单"找到 dwd 表 → 查看血缘上游 → 对话发布"近30天下单用户数"为 API → 生成 AK/SK → curl 调用成功 → 审计页可见调用记录。

### Phase 4 · 打磨与 GA（W15-W16，2 人周）

- W15：权限细化验证（四角色×全模块矩阵）、审计补全、告警打磨、部署脚本加固、备份策略
- W16：集成测试、边界用例、使用文档、**缓冲 0.5 周**（必有超支，预留它）
- **M4（GA）验收**：三个角色各走一遍核心旅程无阻塞；一周试运行，任务失败告警与恢复闭环

## 风险与应对

| 风险 | 概率 | 应对 |
|---|---|---|
| AI 生成任务准确率不达标 | 中 | 澄清反问兜底 + 校验链硬门槛 + few-shot 持续补样例；注释规范 W2 起执行 |
| Airflow 动态 DAG 渲染踩坑 | 中 | W4 专项先行，风险前置；备选方案 DolphinScheduler API（结构不变） |
| 血缘解析覆盖不全 | 中 | v1 只解析 INSERT INTO ... SELECT 主干，解析不了的标注"血缘缺失" |
| 单人进度超支 | 高 | W16 已预留缓冲；M1 是价值锚点，若超支优先保 M1 砍 P1.5 |
| Doris 类型映射边角问题 | 低 | 知识库表可持续补；试跑 100 行兜底暴露问题 |

## 启动清单（W1 第一周，随时可开工）

1. `git init` monorepo：`app/`（FastAPI）+ `web/`（Vue3）+ `deploy/`
2. `deploy/docker-compose.yml`：MySQL + Doris（FE/BE）+ Airflow（LocalExecutor）+ DataX + Nginx，一键 up
3. auth：用户/角色/权限表 DDL + JWT 登录 + RBAC dependency
4. 前端：登录页 + 主布局 + 空路由
5. 验收：`docker compose up` 后浏览器可登录空壳平台
