# 11 · 对照评估：外部大数据平台架构图 vs DataPilot（2026-11-05）

> 对照对象：某大数据平台架构图（数据存储/数据汇聚/数据治理/数据图谱/数据服务/全域数据安全保障 六层）。
> 结论：**八成模块已有等价实现，4 项值得补齐（T1），3 项值得规划（T2），其余明确不做。**
> 评估原则：按 DataPilot 定位（内部数据团队、AI-Native、单人自研）过滤"大厂销售驱动"模块。

## 一、逐模块对照

### 1. 数据存储（多类型数据库）

| 图中项 | DataPilot 现状 | 评估 |
|---|---|---|
| MySQL / Oracle | ✅ 已接 | — |
| SQL Server | ❌ | **T3：值得接**（pymssql 纯 Python，半天；按真实需求触发） |
| 达梦 | ❌ | 国产化需求出现时再接（dmPython） |
| MongoDB / 图数据库 / 内存库 | ❌ | **不做**：NoSQL 走专用通道成本高、内部场景低频 |

### 2. 数据汇聚

| 图中项 | 现状 | 评估 |
|---|---|---|
| 单表同步 / SQL 同步 | ✅ 同步任务（表/自定义查询） | — |
| **整库同步** | ❌ | **T1：值得做**——选库→按表清单批量生成同步任务（循环调现有 create+publish），迁移场景高频，成本低 |
| 多表同步 | ⚠️ 手工逐个建 | 整库同步落地即覆盖 |
| **文件集成（CSV/Excel/TXT/JSON）** | ❌ | **T1：值得做**——业务用户最高频需求（Excel 上传统计入仓）；上传→推断类型→建表→批量导入，成本低收益高 |
| 服务集成（HTTP/WebService） | ❌ | **暂缓**：低频，脚本可替代 |
| 批流一体 | ❌ | **不做**：无流处理场景，FTAP 伪需求 |
| 调度策略引擎 | ✅ cron + 依赖 + 重跑 | — |
| 告警监控 | ✅ 任务失败 + 数据监控 7 类规则 | — |
| 日志管理 | ✅ 实例日志 + 审计 | — |

### 3. 数据治理

| 图中项 | 现状 | 评估 |
|---|---|---|
| 数据质检（规则/监测/告警） | ✅ 监控模块 7 类规则（空值率/唯一性/行数波动/阈值/延迟/自定义SQL/任务时长）+ 通道告警 | **等价覆盖**，不必另起"质检模块" |
| **数据比对**（源目一致性/量级规则） | ❌ | **T2：值得做**——同步任务的质量闭环：源目行数比对 + 抽样字段校验 + 报告；迁移与定期校验刚需，中成本 |
| 数据清洗（清洗规则/异构转换） | ⚠️ | **不做独立模块**：ETL 的 SQL 节点就是清洗手段，重复建设 |
| 数据标准化 | ⚠️ | 暂缓（依赖"数据标准"体系，内部平台收益低） |

### 4. 数据图谱

| 图中项 | 现状 | 评估 |
|---|---|---|
| 元数据查询 / 数据字典 | ✅ 元数据管理（表/字段/注释/样例值） | — |
| 数据血缘 | ✅ 任务级血缘（sync+SQL 解析）+ 血缘图 | — |
| 数据地图 / 数据目录 / 资产统计 | ✅ 资产地图（搜索/标签/Owner/详情/样例） | — |
| 元数据模版管理 / 数据录入 | ❌ | **不做**：采集自动化已覆盖，手工录入模版是低频伪需求 |
| **数据授权**（行/列级） | ⚠️ 仅角色+资源 Owner | 列级脱敏（T1）落地后已覆盖主要合规诉求；行级权限暂缓 |

### 5. 数据服务

| 图中项 | 现状 | 评估 |
|---|---|---|
| API 服务注册（库表服务） | ✅ SQL 模板→API | — |
| 服务鉴权 / 网关负载 / 缓存 / 监控 | ✅ AK/SK 签名 + 限流 + TTL 缓存 + 调用日志 | — |
| **服务脱敏** | ❌ | **T1：随列级脱敏一并做**（数据服务出参套用同一脱敏规则） |
| 引用服务 / 文件服务 / 地理服务 | ❌ | 暂缓（低频） |
| 服务申请（审批流） | ❌ | **不做**：内部平台口头/工单审批即可 |

### 6. BI 可视化

| 图中项 | 现状 | 评估 |
|---|---|---|
| BI 分析 / 仪表 / 大屏 / 报表 | ⚠️ 问数出图（轻量） | **T2：外挂 Superset**（数据源打通 + 入口集成），不自研大屏/报表引擎 |

### 7. 全域数据安全

| 图中项 | 现状 | 评估 |
|---|---|---|
| 凭据加密 | ✅ Fernet | — |
| RBAC + 资源授权 | ✅ | — |
| **列级数据脱敏** | ❌ | **T1：值得做**——脱敏规则表（列→掩码策略）+ 查询/问数/数据服务出参统一后处理；合规刚需，低成本 |
| 数据分类分级 / 加密处理 / 分级策略 | ❌ | **暂缓**：合规驱动项，出现监管要求再做 |
| 数据生命周期管理 | ❌ | **T3：值得做**——表级保留策略（保留 N 天→定时清理分区/数据），复用调度+监控框架，成本低 |
| 任务状态监控 | ✅ | — |
| **服务器状态监控** | ❌ | **T2：值得做**——psutil 采集 CPU/内存/磁盘 + 监控页展示 + 阈值告警，半天 |

## 二、建议清单（按价值/成本排序）

### T1 · 建议下轮做（合计约 3~4 天）
1. **文件集成**：CSV/Excel/TXT/JSON 上传 → 类型推断建表 → 入仓（数据集成新入口）
2. **列级数据脱敏**：规则配置（手机号/身份证/自定义正则掩码）+ 查询工作台/问数/数据服务出参统一套用
3. **整库同步**：选源库+目标库 → 批量生成单表同步任务（含排除表清单）

### T2 · 规划（按需启动）
4. **数据比对**：同步任务附属"源目一致性校验"（行数+抽样比对+报告）
5. **Superset 外挂集成**：BI 可视化（数据源同步+菜单入口，不自研报表）
6. **服务器状态监控**：psutil 采集 + 展示 + 阈值告警
7. **SQL Server 数据源**：pymssql 半天

### T3 · 顺手项
8. **数据生命周期**：表级保留策略 → 定时清理任务（复用调度框架）

### 明确不做（与定位冲突）
- 批流一体、WebService/HTTP 服务集成、数据清洗独立模块、服务申请审批流、
  元数据模版管理、数据分级分类全套、MongoDB/图数据库/内存库、自研大屏报表引擎

## 三、一句总评

图中六层里，DataPilot 已覆盖"汇聚（库表）、治理（质检）、图谱（元数据/血缘/地图/字典）、服务（API/鉴权/缓存/监控）、安全（凭据加密/RBAC/审计）"的核心闭环；
**真正值得补的其实是四个"数据团队每天都在用"的东西：文件入仓、脱敏、整库迁移、源目比对**——都是围绕现有同步/查询链路的自然延伸，而非新模块。
